# OmniRoute + DSH: управление моделями

Текущее состояние: **одна запись на модель плюс группа `DSH-Auto`**. Kiro FREE — основной путь, Z.AI GLM-4.7-Flash — последний резерв. Codex через ChatGPT Plus отключён в OmniRoute, удалён из всех маршрутов и исключён из разрешённых подключений ключа DSH. Эта настройка не меняет подключение самого приложения Codex, в котором велась настройка.

В DSH сейчас по умолчанию выбрана внешняя модель `deepseek-account/deepseek-flash` — она не идёт через OmniRoute и в эту настройку не входит. Маршруты OmniRoute доступны при выборе провайдера `omniroute`.

| Запись в DSH | Что внутри |
|---|---|
| `DSH-Auto` | Автовыбор из всех шести моделей: пять Kiro + GLM |
| `DSH-Sonnet` | `kr/claude-sonnet-4.5` |
| `DSH-DeepSeek` | `kr/deepseek-3.2` |
| `DSH-Qwen` | `kr/qwen3-coder-next` |
| `DSH-MiniMax` | `kr/minimax-m2.5` |
| `DSH-Haiku` | `kr/claude-haiku-4.5` |
| `DSH-GLM` | `glm/glm-4.7-flash` |

Отдельная запись — это ровно одна модель: OmniRoute не подменяет её при ошибке. Если такая модель вернула 429, запрос завершится ошибкой, и модель нужно выбрать вручную. `DSH-Auto` наоборот переключается между моделями сам. Субагенты DSH настроены на `DSH-Haiku` и `DSH-MiniMax`, чтобы не тратить основную квоту на делегирование.

Сколько это выдерживает по лимитам и когда квота кончается — в отдельном разборе: [лимиты бесплатных моделей](docs/omniroute-dsh/limits.md).

## Где управлять

Откройте [OmniRoute](http://127.0.0.1:20128). Пароль заменён при настройке; способ получить его из зашифрованной резервной копии описан в [инструкции восстановления](docs/omniroute-dsh/restore.md#normal-operation). Секреты в README не хранятся.

- **Providers / Провайдеры** — включение и отключение аккаунта целиком.
- **Combos** — список моделей внутри каждого маршрута и порядок резервирования.
- **API Keys / Ключи** — разрешённые маршруты и подключения для ключа `DSH`.
- В DSH **Settings → Models** — локальный провайдер `omniroute` и отображаемые маршруты. Выбор другой модели в беседе сам по себе не отключает аккаунт в OmniRoute.

## Отключить одну модель

1. В OmniRoute откройте **Combos** и нужный `DSH-*` маршрут.
2. Удалите модель из его списка, сохраните. Это удаление из маршрута, а не удаление аккаунта.
3. Повторите для остальных маршрутов, где она встречается. Чтобы модель полностью перестала выбираться автоматически, её нужно убрать из всех используемых маршрутов.
4. Оставьте хотя бы одну проверенную модель в каждом маршруте. Для `priority` порядок означает основной и резервный варианты; `auto` выбирает из всего списка.

Изменения применяются к последующим запросам. Уже выполняющийся запрос может закончиться на прежней модели.

## Включить модель Kiro обратно

1. В **Providers** убедитесь, что подключение Kiro активно и его квота доступна.
2. В **Combos** добавьте в нужные маршруты проверенный идентификатор: `kr/claude-sonnet-4.5`, `kr/qwen3-coder-next`, `kr/deepseek-3.2`, `kr/minimax-m2.5` или `kr/claude-haiku-4.5`. Сохраните порядок и стратегию.
3. Ключ `DSH` уже разрешает аккаунты Kiro и GLM и четыре маршрута, поэтому его менять не требуется.
4. Отправьте короткий запрос через соответствующий маршрут в DSH. Каталог не гарантирует доступность: например, ранее рекламируемый `kr/claude-sonnet-5` был отклонён самим Kiro и не используется.

Чтобы добавить другую модель, сначала подтвердите её реальный ID, доступность именно на бесплатном тарифе и работу инструментов. Не добавляйте платный API как резерв.

Разбор доступных бесплатных вариантов — что уже проверено, что можно добавить и что исключено: [бесплатные модели](docs/omniroute-dsh/free-model-candidates.md).

## Отключить провайдера целиком

В **Providers** выключите нужное подключение переключателем активности. Для защиты от случайного включения также уберите его модели из Combos и аккаунт из разрешённых подключений ключа `DSH`. Не оставляйте список разрешённых подключений пустым: в этой настройке пустой список может означать отсутствие ограничения.

Именно так сейчас изолирован Codex: подключение выключено, `cx/*` отсутствует в маршрутах, ключ DSH разрешает только Kiro. OAuth-запись сохранена, чтобы отключение было обратимым; новые запросы через выключенное подключение не маршрутизируются. Если нужно полностью отозвать ранее выданное разрешение, сделайте это отдельно в настройках аккаунта OpenAI.

## Если когда-нибудь понадобится вернуть Codex Plus

Это снова начнёт расходовать лимиты вашей платной подписки. Для осознанного включения потребуется выполнить все три действия:

1. В **Providers** включить существующее подключение Codex; при истёкшей авторизации пройти официальный вход заново.
2. В настройках ключа **DSH** добавить это подключение в разрешённые, сохранив Kiro. Самому ключу не нужны права управления сервером.
3. В нужных **Combos** явно добавить проверенную модель Codex. Ранее работали `cx/gpt-6-sol`, `cx/gpt-6-astra`, `cx/gpt-6-luna`; доступность нужно проверить повторно на момент включения.

Одного включения аккаунта недостаточно для текущих маршрутов: они содержат только Kiro и GLM. Пока подписка не нужна в DSH, оставьте все три ограничения как есть.

## Проверка и резервные копии

Текущий снимок без секретов: [configuration.json](docs/omniroute-dsh/configuration.json). После ручных изменений обновите его, если используете сравнение конфигурации в тестах.

Из PowerShell в этом каталоге:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
& .\scripts\verify.ps1
```

Проверка отправляет короткие реальные запросы и расходует немного бесплатной квоты. Она сверяет маршруты со снимком, проверяет код и tool calling на шести маршрутах Kiro, отключение Codex и ограничение ключа Kiro и GLM. `DSH-GLM` проверяется отдельно — `scripts/test-glm.ps1`, потому что бесплатный тариф Z.AI отвечает 429 сериями и обычная проверка из-за этого была бы нестабильной. Ошибку квоты не следует обходить подключением платных API.

Старые отчёты первоначальной настройки описывают состояние с Codex Plus; этот README и актуальный JSON отражают последующее отключение. Старый внешний снимок `configured` также содержит включённый Codex: не восстанавливайте его без повторного отключения подписки. Новая копия после отключения хранится отдельно, её путь указан в [отчёте отключения](docs/omniroute-dsh/codex-disabled.md).

## Репозиторий

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) на каждый push и pull request проверяет три вещи: JSON разбирается, все `.ps1` проходят синтаксический разбор, в файлах нет строк, похожих на секреты. Эти проверки не обращаются к OmniRoute — реальные запросы выполняет только `scripts/verify.ps1`.

Скрипты используют `%USERPROFILE%` и `%APPDATA%`, поэтому не зависят от имени пользователя. Ключи и пароль по-прежнему берутся из DPAPI-файлов в каталоге резервных копий; в репозитории их нет.
